# Contribuição

1. Abra uma issue descrevendo o problema, comportamento esperado e forma de reprodução, sem credenciais ou dados pessoais.
2. Crie uma branch curta por mudança e mantenha a organização existente de módulos.
3. Atualize README e documentação quando alterar contratos, variáveis ou fluxos.
4. Execute os comandos de verificação documentados no README. Informe separadamente testes executados e integrações não verificadas.
5. No pull request, descreva problema, solução e validação. Use dados fictícios em capturas e exemplos.

Não faça mudanças de esquema em bases compartilhadas sem revisar migrações e recuperação. Não versione .env, tokens, dumps ou exportações de usuários.
